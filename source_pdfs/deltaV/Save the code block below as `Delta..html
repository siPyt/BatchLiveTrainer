3. Equipment Modules: Command-Driven vs. State-Driven
Module 5 (Slides 5-8 to 5-43)

Both EM types use the exact same interface when commanded by a Phase: write a Named Set state to A_COMMAND, and wait in the transition for A_PV to equal that state. Every EM Named Set must include 255 = Idle.

Command-Driven EM (BLENDER_COLOR)

  • When to Use: Multi-step sequences or timing relationships (e.g., 2-stage Bulk/Dribble valve or pump start/stop).
  • How It Works: Generates a separate SFC sub-block (COMMAND_00001, COMMAND_00002, etc.) for each state in your Named Set (EM-vlvnc-2stage).
  • Key Flag: A_ABT_ON_NEW_CMD (Default = False, finishes current command before running a new one; if True, aborts immediately on new command).

State-Driven EM (BLENDER_OUTLET)

  • When to Use: Simultaneous alignment of multiple valves/motors with no sequential timing (e.g., Product vs. Waste manifold).
  • How It Works: Configured via a Truth-Table Matrix:
    • Items tab: Maps Write Path to Readback Path.
    • States tab: Defines target setpoints/modes per state.
  • Critical Restriction: Only Module-level parameters (MODE, CAS_SP, PV) can be used in the Write/Readback paths!
4. Unit Aliases & Module Ownership Rules
Slides 2-8 to 2-12, 4-12 & 5-25

2 Ways Aliases Are Created on a Unit Class

  1. Manual Aliases (Module 4 — COLORTANKS): Right-click Unit Class → New → Alias (creates blank pointers INLET_VLV, OUTLET_VLV, TANK_LEVEL). You manually type the paths in each Unit Module's Aliases folder.
  2. Auto-Generated via Embedded Classes (Module 5 — BLENDERS): Add EM Classes and CM Classes directly to the Unit Class with Private ownership. Instantiating UM_BL_500 automatically creates all child EMs/CMs and auto-resolves their Aliases! (Shared ownership creates an <unbound> placeholder for shared headers).

Alias Resolution Depth Rule (Slide 2-8 vs. 2-12)

  • Level Transmitters (TANK_LEVEL): Resolved all the way down to the parameter (LI-104/AI1/PV.CV) because the Phase only ever reads PV.CV.
    Usage: '//#TANK_LEVEL#' >= '^/R_FILL_LEVEL.CV'
  • Valves, Motors & EMs (INLET_VLV, OUT_PUMP): Resolved only to the Module Name (XV-101, MTR-505) because the Phase must touch /MODE.TARGET, /CAS_SP.CV, and /PV.CV.
    Usage: '//#INLET_VLV#/PV.CV' = 'vlvnc-pv:OPEN'
5. Device Control Modes (CAS vs. AUTO) & Parameter Promotion
Slides 2-9 to 2-12 & 4-44
  • Why Promote Parameters to the Module Level? On valves (XV-101, XV-502), input CAS_SP is wired to DC1/CAS_IN_D, output PV is wired from DC1/PV_D, and an unwired Internal Reference parameter MODE points to DC1/MODE. This exposes //XV-101/MODE.TARGET at the top of the module (required for State-Driven EMs!). On motors (MTR-505) where MODE and PV were not promoted, paths must reach inside DC1 (//MTR-505/DC1/MODE.TARGET and //MTR-505/DC1/PV_D.CV).
  • PLC vs. DeltaV Mode Terminology on Discrete Devices (DC1):
    • CAS (Cascade Mode) = Batch Phase / EM Control: The DC1 block listens to the CAS_IN_D (CAS_SP) pin. Always drive MODE.TARGET := CAS before (or in the same step as) writing to CAS_SP.CV.
    • AUTO (Automatic Mode) = Normal Operator HMI Control: The DC1 block listens to the operator's faceplate buttons (SP_D). Always return MODE.TARGET := AUTO at the end of a Phase (and in STOP_LOGIC / ABORT_LOGIC) to return control to the operator.
6. S88 Phase State Machine & Expression Syntax Cheat Sheet
Slides 4-15 to 4-23 & 4-53

Phase Parameter Types (Slide 4-15): Batch Input Parameter (Green icon, recipe value sent down to phase, e.g., R_FILL_LEVEL) | Batch Report Parameter (Yellow icon, actual value reported up at end of phase, e.g., RPT_FNL_LVL) | Phase Algorithm Parameter (internal phase variable).

S88 States (Slide 4-17 & 4-53): Resting States (no SFC): Idle, Complete, Held, Stopped, Aborted. Active States (contain SFCs): Running (RUN_LOGIC) → on Hold/Fail enters Holding (HOLD_LOGIC) → rests in Held → on Restart enters Restarting (RESTART_LOGIC) → returns to Running.
