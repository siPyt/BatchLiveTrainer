Chapter 1: Batch Process Overview

1. Core Principles & the ISA-88 (S88) Standard

The primary objectives of the ANSI/ISA-88 (S88) standard are to provide a common, consistent model for the design and operation of batch manufacturing plants and batch control systems, and to improve control and efficiency in batch manufacturing processes[cite: 4, 5].

       PHYSICAL MODEL                     PROCEDURAL CONTROL MODEL
       
        Enterprise                               Procedure
            │                                        │
           Site                                Unit Procedure
            │                                        │
           Area                                  Operation
            │                                        │
       Process Cell                                Phase
            │
          Unit
            │
    Equipment Module
            │
     Control Module

The Four S88 Models

  • Physical Model: Defines a hierarchy consisting of several levels that identifies equipment used within an enterprise[cite: 5, 6].
  • Procedural Control Model: Defines the hierarchy of actions and control that enables equipment to perform process tasks and complete a batch[cite: 5, 6].
  • Control Activity Model: Defines the relationships between the various control activities required to perform batch processing (such as recipe management and scheduling)[cite: 5].
  • Process Model: Defines the results and transformations of performing procedural control on the equipment in the process[cite: 5].

Physical vs. Procedural Hierarchies

Level Physical Model Entity Procedural Control Model Entity Scope & Role
Top Level Process Cell Procedure A Process Cell is a logical grouping of units containing all equipment required for the production of one or more batches[cite: 8]. A Procedure executes a sequence of unit procedures using one or more units to produce a product batch, representing the procedural hierarchy's highest level[cite: 13, 14].
Mid-High Level Unit Unit Procedure A Unit represents a logical grouping of similar equipment (e.g., blenders, reactors, storage tanks) capable of running independently[cite: 9]. A Unit Procedure is a collection of operations, transitions, and parameters that executes a sequence of operations to perform a certain function on a specific unit[cite: 12].
Mid Level Equipment Module (EM) Operation An Equipment Module provides supervisory control for a collection of control modules, typically coordinating them via states or commands[cite: 10]. An Operation executes a sequence of unit phases, transitions, and parameters to perform a certain function on a specific unit[cite: 12].
Lowest Level Control Module (CM) Phase (Unit Phase) A Control Module links algorithms, conditions, alarms, and displays together and is the lowest-level grouping of equipment that carries out basic control[cite: 10]. A Phase (Unit Phase) contains user-defined parameters and logic to accomplish a specific process-oriented task (such as Fill, Dump, Agitate, or Drain)[cite: 12]. Up to 10 unit phases may run simultaneously on the same unit module[cite: 12].

Core Applications

  • Batch Executive: An application running as a Windows XP service that executes recipes[cite: 14]. Operators interact with the Batch Executive via the Batch Operator Interface and DeltaV Operate[cite: 14]. DeltaV supports up to four Batch Executives on a single network[cite: 14].
  • Batch Operator Interface (BOI): The graphical interface used by operators to interface with the Batch Executive for loading and running batches and recipes[cite: 16].
  • Control Studio: Used to create and edit control modules and phase logic[cite: 16].
  • Recipe Studio: Used to create and edit operations, unit procedures, and procedures[cite: 16].
  • Campaign Manager: Used to run multiple iterations of a batch; it must run on the same node as the Batch Executive[cite: 16].
  • Batch Historian & Batch History View: The Batch Historian collects Batch Event Journal files from the Batch Executive and Event Chronicle records, storing them in an SQL database[cite: 16]. Batch History View is used to view this historical batch data[cite: 16].
  • Version Control: Runs on the ProfessionalPLUS workstation and utilizes an SQL database to record and track configuration changes[cite: 16].

3. Class-Based Architecture & Aliasing

DeltaV enables the creation of reusable logic templates that can be incorporated across multiple instances to reduce configuration effort[cite: 7].

Class Template (Library) → Instantiate → Instance (Plant Area / Controller)[cite: 7, 22]

  • Class: A template from which objects are created under Library → Advanced Definitions[cite: 7, 18]. Common properties apply to all instances[cite: 7].
  • Instance: An individual object created from a class, possessing identical structure and properties to other instances of that class[cite: 7].
  • Allow instance value to be configured: Checking this property box in the class properties dialog allows an instance to override the default library value[cite: 21]. The system cannot upload the parameter unless this box is checked[cite: 21]. If unchecked later, instances overriding the class value revert back to the class default[cite: 21].
  • Aliases: Created at the Unit Class level to represent individual equipment items associated with a set of units, and resolved to specific module paths at the Unit Module level[cite: 9, 79].

4. Chapter 1 Step-by-Step Workshop Guide

This hands-on workshop guides you through creating a reusable Analog Input Control Module Class (LEVEL_INDICATOR), instantiating it across five tank level transmitters, configuring instance overrides, and downloading to the controller[cite: 25, 27, 28].

Step 1: Create a Control Module Class Category

  1. Open DeltaV Explorer[cite: 18].
  2. Navigate the directory tree: DV_School → Library → Advanced Definitions[cite: 18, 25].
  3. Right-click on Control Module Classes and select New Category[cite: 18, 25].
  4. Name the category AnalogInput[cite: 18, 25].

Step 2: Create the LEVEL_INDICATOR Control Module Class

  1. In DeltaV Explorer, expand DV_School → Library → Module Templates → Monitoring[cite: 19, 25].
  2. Locate the template named ANALOG[cite: 19, 25].
  3. Drag and drop the ANALOG template into the new Control Module Class category: DV_School → Library → Advanced Definitions → Control Module Classes → AnalogInput[cite: 19, 25].
  4. Rename the new class to LEVEL_INDICATOR[cite: 19, 25].

Step 3: Configure Module Class Logic in Control Studio

  1. Right-click LEVEL_INDICATOR and select Open with Control Studio[cite: 20].
  2. Select the AI1 function block and modify the parameters[cite: 26]:
    • OUT_SCALE: Set scale from 0 to 500 gal, and check Allow instance value to be configured[cite: 21, 26].
    • L_TYPE: Set to Direct[cite: 26].
    • HI_LIM: Disable the HI ALM[cite: 26].
    • LO_LIM: Disable the LO ALM[cite: 26].
    • SIMULATE: Set to Enabled, with value 0[cite: 26].
  3. From the Special Items palette, drag and drop an Input Parameter onto the diagram[cite: 26].
  4. Name the parameter LEVEL_IN, set parameter type to External Reference, and leave the path unconfigured (DO NOT BROWSE for the external parameter path at this stage)[cite: 26].
  5. Wire the output of the LEVEL_IN parameter block to the SIMULATE_IN terminal of the AI1 function block[cite: 26].
  6. Open Module Properties and set the Primary Display to Process[cite: 26].
  7. Save your work and exit Control Studio[cite: 26].

Step 4: Create Control Modules from the Class

  1. Drag and drop the Control Module Class LEVEL_INDICATOR to the Plant Area ED_CENTER_BATCH (under System Configuration → Control Strategies)[cite: 22, 27].
  2. Expand ED_CENTER_BATCH and rename the new module from LEVEL_INDIC_1 to LI-104[cite: 27].
  3. Drag and drop LEVEL_INDICATOR into ED_CENTER_BATCH and rename to LI-204[cite: 27].
  4. Drag and drop LEVEL_INDICATOR into ED_CENTER_BATCH and rename to LI-304[cite: 27].
  5. Drag and drop LEVEL_INDICATOR into ED_CENTER_BATCH and rename to LI-504[cite: 27].
  6. Drag and drop LEVEL_INDICATOR into ED_CENTER_BATCH and rename to LI-604[cite: 27].

Step 5: Configure Instance Parameters & Simulator References

  1. Select LI-104, open LEVEL_IN properties, and set the external parameter path to TANKSIM/TKLEV100[cite: 27].
  2. Select LI-204, open LEVEL_IN properties, and set the external parameter path to TANKSIM/TKLEV200[cite: 27].
  3. Select LI-304, open LEVEL_IN properties, and set the external parameter path to TANKSIM/TKLEV300[cite: 28].
  4. Select LI-504:
    • Set the external parameter path for LEVEL_IN to LEV500-SIM/500_LEV[cite: 28].
    • Open properties for AI1$OUT_SCALE, uncheck Use default value from library object, and change the 100% scale to 1000 (configuring 0-1000 gal)[cite: 24, 28].
  5. Select LI-604:
    • Set the external parameter path for LEVEL_IN to LEV600-SIM/600_LEV[cite: 28].
    • Open properties for AI1$OUT_SCALE, uncheck Use default value from library object, and change the 100% scale to 1000 (configuring 0-1000 gal)[cite: 24, 28].

Step 6: Assign, Download, and Verify

  1. Drag and drop the plant area ED_CENTER_BATCH onto your controller node[cite: 28].
  2. Download your Controller (there is no need to perform an upload)[cite: 28].
  3. Verify that the configuration executes correctly without unresolved reference errors[cite: 28].
