1. WHAT IS KNOWN (with source)
------------------------------

A) New Phase Class dialog (slide 4-14, PDF page 66)

   - Object type ("Phase Class") and Browse are greyed too. Start From Existing is available.
   - BatchLiveTrainer now matches this: Phase Algorithm only, greyed; Start From Existing works.
   - NOTE: an earlier change added a "No Algorithm" choice. That was NOT backed by a source and
     has been removed.

B) Equipment Module Class algorithm types (slides 5-8 / 5-9, PDF pages 124-125)
   The course says there are seven, with these definitions:
   1. Function Block Diagram - interconnected standard DeltaV function blocks; you define the
      blocks, their parameters and how they work together.
   2. Sequential Function Chart (SFC) - a sequence of events with steps, transitions, actions.
   3. Command-Driven - SFC code based on commands. Selects one of a number of command sub-blocks
      based on the value written to A_COMMAND (named set; one entry per command plus the
      mandatory 255 undefined/idle entry).
   4. State-Driven - SFC code based on states. A single step or value manipulates the control
      modules; for simple equipment manipulation without complex timing (e.g. changing the
      setpoints of a group of valves or motors).
   5. Phase Algorithm - a state transition diagram made up of embedded composites that hold the
      logic governing the transitions between the states of a phase.
   6. Phase with command-driven run logic - the run logic composite is replaced by a
      command-driven composite.
   7. Phase with state-driven run logic - the run logic composite is replaced by state-driven
      logic.
   - All seven are in the dropdown, and each shows the course definition (with page) when chosen.
   - SIMULATED: 3 (Command driven) and 4 (State driven) - used by Chapter 5 (BLENDER_COLOR,
     BLENDER_OUTLET), with Control Studio editing, download, A_COMMAND / A_PV and the workshops.
   - NOT YET SIMULATED: 1, 2, 5, 6, 7. Choosing one and pressing OK shows a message saying so.

C) Unit Class dialog (slide 4-11)
   - Algorithm type is shown as "<None>" (greyed). The course does not show any other choice.

D) Unit phase "Phase type" (slide 4-29, PDF page 81) - already simulated:
   Controller (downloaded with the unit module), Disabled (ignored during downloads),
   External Phase (exists outside the DeltaV system database).

5. CONFIRMED BY THE PDF WHILE CHECKING (phase logic, needed for Chapter 6 and later)
-----------------------------------------------------------------------------------
   - Slide 8-7 "Talking With Your Phase": BCOMMAND (Batch Executive) and XCOMMAND (phase owner
     External) both use: 10 Abort, 20 Hold, 30 Stop, 40 Reset, 50 Pause, 60 Single Step,
     70 Download, 80 Resume, 90 Restart, 100 Start, 110 Automatic, 120 Manual, 130 Clear Failures.
     REQUEST: 0 Clear Message, 1000 Download Parameters, 2000 Upload Parameters.
   - Slide 6-32: the Failure Monitor continuously monitors failure conditions and sets FAIL_INDEX
     to the failure number; when FAIL_INDEX is non-zero the phase goes to Holding.
   - Slides 6-33 / 6-34: failure numbers come from the phase_failures named set
     (0 Ok, 1 Watchdog, 2 Write Req., 3 Switchover, then user failures such as Agitator stopped,
     Product vlv open ...). FAIL_MONITOR uses a BFI block (FIRST_OUT, OUT_D, IN_D1..5) and a CALC
     block; conditions can be enabled/disabled from RUN_LOGIC (6-42 .. 6-44).
   - Slides 6-16 .. 6-20, 6-42 .. 6-44: RUN_LOGIC actions WRITE STEP_INDEX (1, 2, 3, 4, 5, 0).
   - Slides 6-26, 6-46, 6-47, 6-50: HOLD_LOGIC and RESTART_LOGIC branch on STEP_INDEX and
     FAIL_INDEX; RESTART_LOGIC sets RESTART_TYPE ('Continue' / 'From_Start', $phase_restart_types).
   - Slide 6-17: PENDING_CONFIRMS step parameter; slide 6-20: step parameter TIME;
     slides 6-18 .. 6-20: BLEND_TIMER linked composite (START, RESET, TIME_DURATION, ELAPSED_TIME).
   - Slide 10-34: recipe transitions use AGITATE:1/BSTATUS = $phase_state:Complete.

   GAPS IN BATCHLIVETRAINER FOUND BY THIS CHECK (to fix before Chapter 6):
   - STEP_INDEX is computed by the simulator and read-only; the course writes it from RUN_LOGIC.
   - FAIL_INDEX is shown as text ('OK') and read-only; the course writes a number from
     FAIL_MONITOR and a non-zero value must drive the phase to Holding.
   - FAIL_MONITOR is an SFC in BatchLiveTrainer; the course builds it as a function block diagram
     (BFI + CALC). RESTART_TYPE, PENDING_CONFIRMS, step TIME, linked composites (BLEND_TIMER)
     and the phase_failures / $phase_restart_types / $phase_state named sets need checking.
   All of these are described in Chapter 6 of the course PDF, so they can be implemented from it
   when Chapter 6 starts (render the slides for the exact screens).
